# 别忘了_验收发布与小白操作手册_V1.1

> **服务对象：** 道一  
> **目标：** 你只承担不可替代的人类权限动作；其余开发、测试、修复、部署和技术排错由Codex推进。

## 一、最终应该拿到什么

### PWA

- 一个HTTPS公网网址；
- 手机浏览器直接打开；
- 可添加到手机主屏；
- Mac Safari可“添加到程序坞”；
- 断网冷启动仍可完成核心检查；
- 刷新 / 重启不丢正在进行的Run；
- 数据页能看到本地保护 / 备份状态；
- JSON完整备份与恢复通过；
- Markdown / TXT可读导出可用；
- 更新和schema迁移不会破坏旧数据。

### 微信

- 小程序工程真实可运行；
- 开发者工具通过；
- 真机预览通过；
- 当前账号条件允许时继续到体验版；
- 具备审核条件；
- 能提交时继续提交；
- 审核通过且账号允许时继续发布。

## 二、你不需要做什么

正常情况下，你不需要：

- 改代码；
- 手工装依赖；
- 看终端报错；
- 自己研究Service Worker；
- 自己修IndexedDB；
- 自己分析微信兼容；
- 自己选择技术栈；
- 自己制作测试矩阵；
- 自己研究如何部署。

## 三、什么情况下Codex可以找你

仅限真实外部权限，例如：

- 登录 / 扫码；
- 选择或提供小程序AppID；
- 微信管理员确认；
- 托管平台授权；
- 账号主体认证；
- 审核 / 发布必须由管理员点击；
- 当前设备真机操作Codex无法代替。

正确方式：

> Codex先做到阻塞点 → 只告诉你最小一步 → 你完成 → Codex继续。

错误方式：

> 还没做到阻塞点，就给你一篇“请自行发布”的教程。

## 四、PWA最小验收

### 1、普通手机浏览器

- 打开真实URL；
- 选择“日常出门”；
- 勾选2项；
- 标记1项“本次不需要”；
- 锁屏 / 切App；
- 回来状态仍在；
- 完成Run；
- 历史可见。

### 2、关键项真实性

- 打开含普通项＋关键项模板；
- 只看关键项；
- 处理完关键项但故意保留一个普通项未处理；
- 系统不得显示`completed`；
- 选择提前结束后必须显示`endedWithUnresolved`语义。

### 3、手机主屏

- 添加到主屏；
- 从图标启动；
- 再跑一次Run；
- 无白屏、底部遮挡、横向溢出。

### 4、离线冷启动

- 联网打开并完成缓存；
- 启动一个Run；
- 完全关闭；
- 开飞行模式 / 断网；
- 从主屏重新打开；
- 继续并完成；
- 再关闭打开，历史仍在。

### 5、Mac

macOS Sonoma 14或更高：

- Safari打开；
- “添加到程序坞”；
- 从Dock启动独立Web App；
- 检查、模板编辑、历史、备份都可用；
- 大屏布局不是简单拉宽手机页面。

## 五、数据可靠性验收

至少做一次：

1. 新建个人模板；
2. 创建Planned Check；
3. 修改来源模板；
4. 从计划启动Run；
5. 确认启动内容仍是计划创建时快照；
6. 完成至少两次Run；
7. 导出JSON；
8. 导出可读文本；
9. 测试环境重置；
10. 恢复JSON；
11. 核对模板、计划、Run、收藏；
12. 用损坏JSON恢复，必须失败且当前数据不受影响；
13. 用未来`backupFormatVersion`恢复，必须明确拒绝。

## 六、写入失败验收

开发测试环境必须能模拟一次持久化失败。

预期：

> 不能出现“界面已经打勾、底层没保存、用户却不知道”。

失败时应：

- 回滚；或
- 明确显示“未保存”。

## 七、微信最小真机验收

至少：

- 首页；
- 继续检查；
- 新开Run；
- `notNeeded`；
- 关键项视图；
- 临时项；
- 切出微信后恢复；
- History；
- 官方模板分享；
- 分享内容默认不带oneTimeNote；
- 本地数据重进后仍在。

## 八、平台提醒的验收口径

V1硬门不是“必须收到系统推送”。

必须有：

> **L0应用内计划提示。**

系统日历、Web Push、微信订阅消息只有当前平台能力可靠时才做。

如果Codex发现平台条件不足，应标记：

> `degraded`或`requires-backend`

而不是伪装“提醒已经设置”。

## 九、什么情况不要接受“已经完成”

如果Codex只说：

- build成功；
- 测试理论通过；
- PWA理论支持离线；
- 微信开发者工具能跑；
- README已经写好；
- 你自己按步骤部署即可；

都不算最终完成。

可以直接要求：

> **继续按V1.1任务书推进到当前环境和账号权限允许的最远真实状态，并给出可检查证据。**

## 十、发布后的使用方式

前两周不要急着继续加普通功能。

先积累约30次真实Check Run，并重点记录：

1. 有没有真实重要遗漏；
2. 用完后还会不会反复回想；
3. 哪个项目让人不知道该“确认 / 本次不需要”；
4. 哪一步让人觉得是在管理工具；
5. 有没有任何数据、离线、恢复、更新异常。

普通新功能先放候选池。
