# 别忘了 V1.1 微信端视觉恢复设计

> 状态：方向 A 已由用户于 2026-08-31 明确选定。本设计只恢复冻结视觉概念中的轻、干净、紧凑层级，不新增产品规则。若与 `docs/01_别忘了_产品定义与冻结规格_V1.1.md`、`docs/02_别忘了_官方模板内容库_V1.1.md`、`docs/03_Codex_别忘了_双端开发_任务书_V1.1.md` 或 `contracts/domain-contract-cases.v1.1.json` 冲突，以这些正式主源为准。

## 1. 问题与目标

2026-08-31 的当前态复拍见 `evidence/wechat/ui-audit-2026-08-31/audit.md`。在微信开发者工具 iPhone 12/13 (Pro)、390 × 844、默认字体档下，首页、模板库、模板详情与 Run 已确认存在共同问题：

- `650/680/720/730/760/780` 等非标准字重在不同系统字体上的映射不稳定；
- 原生 `button` 没有统一内容居中模型，长中文标签和较大字体档存在基线与回流风险；
- 卡片、完整边框、圆角、阴影和粗体使用过量；
- 模板低频管理动作全部平铺，Run 的排序与备注长期展开；
- Run 在 390 × 844 一屏约显示 2.5 个项目，明显低于快速核对所需密度；
- 当前实现与 `docs/design/visual-concept-v1.1.png` 所表达的开放列表、分组清单和克制层级不一致。

本次目标：在不改变任何业务事实的前提下，把 11 个微信原生页面恢复为“同一产品的微信原生轻工具版本”，优先提高文字稳定性、首屏可读性和 Run 核对效率。

## 2. 不变边界

视觉整改不得改变：

- 13 个官方模板、官方文案、顺序、身份或内容版本；
- Official / Personal Template 治理规则；
- Planned Snapshot、Run Snapshot、三状态与关闭/重开语义；
- 首页继续 Run、计划、常用与精选的确定性排序；
- durable write 成功后才发布页面成功的顺序；
- 双槽存储、备份/恢复、分享隐私和 Local-first 边界；
- 11 个原生页面和现有导航目标；
- 测试 AppID、无账号、无云同步、无 AI、无 Analytics、无远程字体或运行时 CDN。

本次不为追求“更好看”重写官方内容，不增加 Onboarding，不把模板详情变成启动前确认门，不用颜色代替状态文字，也不把微信端改成 PWA 的网页翻版。

## 3. 视觉基准与设计原则

视觉关系以 `docs/design/visual-concept-v1.1.png` 为基准，产品内容以正式 Markdown 为准。实施遵循：

1. **内容先于容器**：普通列表使用开放式分隔行；只有继续 Run、结束回执、表单、危险说明等真实聚合信息使用容器。
2. **一个区域一个主动作**：低频管理动作进入详情页或按需展开，不在列表卡中平铺五个按钮。
3. **核对优先**：Run 首屏优先显示项目，不让说明、排序和备注占据长期空间。
4. **标准字体度量**：只使用 400、500、600、700 四档字重，并为每级文字定义明确行高。
5. **原生但不粗糙**：保留微信导航、反馈和分享；统一按钮内容盒、安全区和回流规则。
6. **温暖而克制**：暖白背景、深绿主色、少量柔和表面；危险色只用于破坏性操作和关键未确认风险。

## 4. 全局设计令牌

### 4.1 颜色

```text
page background      #F7F7F3
primary surface      #FFFFFF
soft surface         #F0F4F1
ink                  #17201E
muted ink            #66716E
primary              #247463
primary strong       #185C4E
border               #DDE3DF
warning              #B85E42
warning soft         #FFF2ED
success soft         #E7F1ED
key soft             #FFF0D5
```

颜色不作为唯一状态信息；`confirmed`、`notNeeded`、`unchecked`、关键项和关闭类型继续保留文字标签。

### 4.2 字体

继续使用系统中文字体栈，不加载字体文件：

```text
font family   -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif
page title    40rpx / 1.22 / 700
section title 30rpx / 1.30 / 700
row title     29rpx / 1.35 / 600
body          26rpx / 1.55 / 400
button        27rpx / 1.20 / 600
meta          23rpx / 1.45 / 400
eyebrow       22rpx / 1.40 / 600
badge         21rpx / 1.20 / 600
```

禁止继续使用非标准中间字重。数字、中文、英文和动态计数必须共享同一行高盒，不能靠 `vertical-align` 或负 margin 目测补偿。

### 4.3 间距与形状

```text
base spacing         16rpx（8px）
page horizontal      32rpx（16px）
page top             24rpx
section gap          32rpx
row vertical         20rpx
button horizontal    24rpx
button radius        20rpx（10px）
surface radius       24rpx（12px）
major group radius   32rpx（16px）
touch target         不小于 88rpx × 88rpx（44px × 44px）
```

普通列表不使用阴影。继续 Run、结束回执等最多使用一层极浅阴影；同一屏不得重复堆叠阴影卡片。

## 5. 共用原生组件模型

### 5.1 Button

所有按钮统一：

- `display: flex; align-items: center; justify-content: center`；
- 最小触控高度 88rpx；
- 水平内边距 24rpx，明确 `line-height: 1.2`；
- 标准字重 600；
- 单行短标签居中；长标签允许最多两行并由高度自然增长，不裁切；
- loading spinner 与标签处于同一 flex 内容盒；
- primary、secondary、text、danger 四级，不再让所有动作都拥有完整边框；
- text button 保留 88rpx 命中区，但视觉上不制造新的卡片。

### 5.2 List row

开放列表行由“主内容 + 右侧状态/计数 + 可选主动作”组成：

- 相邻行用 1rpx 分隔线；
- 标题可换行，计数和状态不可压缩标题到不可读；
- 行内徽标使用独立 flex 子项，与标题按中心线对齐；
- 行本身可执行的动作必须与按钮动作一致且可解释，避免一个触控区同时承担开始和详情。

### 5.3 Group surface

只有一组相关行需要共同边界时使用 group surface。组标题位于容器外或容器顶部；组内普通项目用分隔线，不为每一项再建卡片。

### 5.4 Disclosure

排序、一次性私密备注、模板治理等低频动作可以按需展开：

- 展开状态只属于当前页面 UI，不写入 AppSnapshot；
- 展开/收起不改变 Run 或 Template 事实；
- 切换视图和页面恢复后，事实仍从 service 重新投影；
- `notNeeded` 是核心三状态之一，不能藏入低频“更多”；排序和备注可以。

### 5.5 Bottom action dock

模板详情与 Run 的主动作使用底部动作区：

- 尊重 `env(safe-area-inset-bottom)`；
- 内容滚动区预留等量底部空间，不遮挡最后一项；
- 模板详情保持“安排计划 / 开始检查”；
- Run 保持“临时加一项 / 结束本次检查”，破坏性“放弃”放入结束语义区而非固定主按钮；
- fixed/sticky 能力不可用时退化为文档流末尾，不能遮挡或丢失动作。

## 6. 页面设计

### 6.1 首页 `pages/home`

严格保持冻结优先级：继续检查 → 接下来最多三项 → 我的常用 → 官方精选。搜索、新建、计划、历史和数据保留清楚入口，但使用紧凑工具行，不抢占内容主层级。

- Hero 收紧为 eyebrow、40rpx 标题、一行/两行说明和安静的本机说明；取消占据整行的强胶囊感。
- 有进行中 Run 时只保留一个聚合式 continue surface；其他 Run 通过明确文字入口进入全部进行中。
- 计划、常用和精选使用开放列表或单一 group surface；不为每个模板单独建立大阴影卡。
- 模板行保留“直接开始”和“详情”，但降低“详情”的视觉权重。
- 空白新状态在 390 × 844 中应看到 Hero、工具入口、官方精选标题和至少两个完整精选模板行。

### 6.2 模板库 `pages/templates`

- 搜索与新建保留顶部双入口。
- “我的模板”“官方模板”使用分组列表；每行显示身份、标题、适用场景、项目数和状态标签。
- 列表层只保留“开始 / 详情”两个高频动作。
- 官方收藏、隐藏、另存个人副本进入模板详情；个人编辑、复制、删除进入模板详情。
- 已隐藏官方入口仍可在模板库识别和恢复；已删除个人模板仍有可恢复区。
- 390 × 844 中，模板库 Header 和工具行之后至少显示四个完整官方/个人模板行，长标题不得横向溢出。

### 6.3 模板详情 `pages/template-detail`

- Header 只承载身份、标题、适用场景和快照说明。
- 治理区为单一轻表面；三个治理动作可以同区排列，但必须允许两行回流且不改变按钮基线。
- 检查项目按组使用 group surface；项目为开放分隔行，关键徽标与标题使用 flex 对齐。
- condition、hint 仅在存在时显示为 23rpx 次要文本。
- 底部动作 dock 固定“安排计划 / 开始检查”，不遮挡 `userTip` 或最后一个项目。

### 6.4 Run `pages/run`

Run 是本次优先级最高的视觉整改面。

- Header 收紧为状态 eyebrow、标题、未确认/关键计数；持久化承诺降为安静 meta，不用强胶囊。
- “全部 / 只看关键”使用紧凑分段控件，保持两个视图的事实计算不变。
- 页面展示层从扁平 `items` 派生为按 `groupTitle` 分组的有序列表；派生不得改变 `runItemId`、排序或 service 输入。
- 每个项目默认只显示组名（组首项）、关键标识、标题、状态、condition/hint，以及“确认 / 本次不需要”两个核心动作。
- 排序和一次性私密备注进入当前项目的按需展开区；展开状态不持久化。
- 已全部处理的组可轻量弱化，但不得自动隐藏未确认事实。
- “临时加一项”通过底部动作打开轻量编辑区；保存仍必须先 durable commit。
- 结束、关键项二次确认、放弃、重开和关闭回执文案完全不变。
- `日常出门` 默认 Run 在 390 × 844 中应同时看到 Header、视图开关和至少四个完整项目标题；任何项目的核心动作不得小于 44px。

### 6.5 其余进行中 `pages/more-runs`

使用开放列表显示标题、未确认数、关键项数、最近交互与 stale 状态；每行一个“继续”主动作。优先 Run 使用柔和底色或左侧标记，不能只靠颜色解释。

### 6.6 计划 `pages/plans`

创建表单保留独立表面，待办计划改为分隔列表。每行只突出“开始”；取消、日历和详情动作降为次级文字按钮。过期是标签，不自动结束或删除。

### 6.7 历史与历史详情 `pages/history`、`pages/history-detail`

历史列表使用开放行，明确显示关闭类型、完成数、未确认数和结束时间。历史详情复用 Run 的只读分组行视觉，但绝不复用可写交互；重开/重新开始继续通过既有 service 路径。

### 6.8 搜索 `pages/search`

搜索框是首要表面；结果为紧凑列表。每行保留匹配原因、来源和“开始 / 详情”，不重复模板库的五操作布局。

### 6.9 个人模板编辑 `pages/template-edit`

保留预览、名称、逐行项目、图标、主题色和长清单软提醒。减少嵌套卡片；表单 label、输入和帮助文字使用统一节奏。图标继续使用现有有限字符集合，本次不新增图像资产或伪造 CSS 图标。

### 6.10 数据 `pages/data`

按“当前保护状态 / 导出 / 导入恢复 / 重置”分组。高风险恢复和重置保持独立警告区；普通能力说明使用开放行。视觉收紧不得弱化“生成不等于异地保存”“当前数据未改变”等信任文案。

## 7. 字体回流与平台适配

- 默认以 390 × 844 和 375px 宽度实现；不得出现横向滚动。
- 动态标题和官方长标题允许换行，不使用固定高度裁切正文。
- 行内状态区允许在窄宽或大字体档下换到下一行；不得覆盖标题。
- 三个以上动作不得强制三等宽单行；允许两列/两行或纵向布局。
- iPhone 安全区底部预留必须覆盖所有 fixed dock；Android 无安全区时不得产生异常大空白。
- 当前模拟器默认字体档是基线；整改完成后至少复验 iOS 默认档、iOS 较大字体档和 Android 默认档。无法由自动化切换的字体档必须明确标为真机/GUI 证据缺口，不能推定通过。

## 8. 状态、错误与可访问性

- loading、empty、error、busy、disabled、confirmed、notNeeded、unchecked、hidden、deleted、stale、completed、endedWithUnresolved、discarded 都必须有可读文本。
- `role="alert"` 和既有模态确认路径保留。
- 点击目标不小于 44px；透明 text button 也必须有完整命中区。
- disabled 的文字和背景仍需可辨识，不用仅降低到不可读透明度。
- 页面阅读顺序与视觉顺序一致；低频展开区紧随所属项目。
- 不声称截图即可证明完整无障碍合规；屏幕阅读器和真机字体仍保留人工门。

## 9. 实现边界

允许修改：

- `miniprogram/app.wxss`；
- 11 页 WXML / WXSS；
- 只为展示分组、展开状态和临时编辑入口所需的页面级 JS 投影；
- 微信页面测试与静态发布门；
- 当前态/整改后截图和发布证据。

禁止修改：

- `packages/domain/`、`contracts/`、官方模板内容或派生 JSON/JS；
- store / service 的持久化协议和领域命令；
- PWA UI；
- 产品版本含义、AppID、账号或云能力。

如果视觉实现被迫修改领域输入、持久化顺序或正式文案，必须停止并重新审查，而不是把它包装成样式调整。

## 10. 验收与证据

实现必须先以测试锁定不变量，再修改界面。至少执行：

```text
pnpm content:check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm verify:boundaries
pnpm miniprogram:verify
pnpm e2e
git diff --check
```

微信专项还必须：

1. 静态检查不再出现非标准数值字重；
2. 现有 11 页、事件处理器、分享入口和 13 模板门保持通过；
3. 官方工具逐页编译通过；
4. 重新捕获同一 390 × 844 的首页、模板库、模板详情、普通 Run；
5. 增补多个进行中 Run、关键项视图、notNeeded、结束确认、完成/未确认结束回执、分享入口等冻结视觉状态；
6. 至少捕获一个 Android 默认字体状态；
7. 对照 `docs/design/visual-concept-v1.1.png` 与整改前截图逐项检查密度、层级、基线、圆角、边框和安全区；
8. 视觉门通过后重新生成预览并上传测试号体验构建，保留真实包大小与工具结果；
9. 物理手机较大字体、聊天文件、日历、分享面板和切后台恢复仍由真实用户手势完成，不以模拟器替代。

## 11. 完成定义

只有同时满足以下条件，才可以声明本次微信视觉恢复完成：

- 冻结文案、数据语义和持久化测试无回归；
- 11 页静态门与官方编译通过；
- 首页、模板库、模板详情、Run 的整改后截图已保存并人工检查；
- Run 密度与按钮基线达到本设计的可测目标；
- iOS 默认与 Android 默认模拟器无横向溢出、遮挡或错位；
- 较大字体档已实测，或明确标记为仍待物理终端完成，绝不推定通过；
- 新体验构建真实上传成功；
- 最终报告准确区分模拟器、体验版和正式发布。

## 12. 自检结论

- 本设计没有新增产品功能、模板内容、账号、云同步、AI、远程字体或新页面；
- 首页优先级、直接开始、三状态、关闭真实性、快照与 durable-write 顺序均保持不变；
- 低频动作只是改变呈现位置，不删除能力；
- 所有动态内容都具有回流策略，不依赖固定高度截断；
- 可测密度目标、设备范围、截图状态和外部证据边界均已明确；
- 文档中的设计决策均已收敛，且没有与正式主源相冲突的产品规则。
